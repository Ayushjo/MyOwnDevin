# MyOwnDevin — Autonomous GitHub Issue Agent

> **Submit a GitHub issue → AI plans → executes in Docker sandbox → opens a PR.**
> Watch every thought, tool call, and LLM step stream live in the browser.

---

## ✨ Features

| Capability | Details |
|---|---|
| 🧠 **AI Planning** | Multi-step plan generated by LLM from the issue description + repo context |
| ⚙️ **Sandbox Execution** | Each task runs in an isolated Docker container — your machine is untouched |
| 🔀 **Auto PR** | On success, a pull request is opened with a clear description and diff |
| 📊 **Live SSE Logs** | Every tool call, agent thought, and LLM metric streams to the browser in real-time |
| 🔐 **GitHub OAuth** | Sign in → your personal token is used to clone/push, no shared bot token needed |
| 📋 **History & Metrics** | Full task history with duration, cost, token counts, and phase timeline |

## 🚀 Quick Start (Local)

### Prerequisites

- Node.js 20+
- Docker Desktop running
- Redis (`brew install redis && brew services start redis`)
- A GitHub OAuth App (see below)
- At least one LLM API key (Gemini, Groq, OpenRouter, or Anthropic)

### 1. Create a GitHub OAuth App

1. Go to **GitHub → Settings → Developer Settings → OAuth Apps → New OAuth App**
2. Set **Homepage URL**: `http://localhost:5173`
3. Set **Authorization callback URL**: `http://localhost:3500/api/auth/github/callback`
4. Copy **Client ID** and generate a **Client Secret**

### 2. Backend Setup

```bash
cd backend
cp .env.example .env
# Fill in your values:
#   GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET
#   SESSION_SECRET  (any long random string, e.g. openssl rand -hex 32)
#   At least one LLM key (GEMINI_API_KEY / GROQ_API_KEY / etc.)
#   GITHUB_TOKEN    (optional fallback for tasks without OAuth)

npm install
npm run dev
# Backend runs at http://localhost:3500
```

### 3. Frontend Setup

```bash
cd frontend
cp .env.example .env.local  # or create it
# Set: VITE_API_URL=http://localhost:3500

npm install
npm run dev
# Frontend runs at http://localhost:5173
```

### 4. Try It

1. Open `http://localhost:5173`
2. Sign in with GitHub (OAuth)
3. Submit a GitHub issue URL (e.g. `https://github.com/your-org/your-repo/issues/42`)
4. Watch the agent plan, execute, and open a PR live

## 🌐 Deploy to Production

### Architecture for Deployment

```
Frontend → Vercel (static)
Redis    → Railway (managed)
Backend + Docker Worker → Fly.io or Render (Docker, needs real Docker daemon)
```

> **Important:** Vercel/Railway cannot run Docker. The backend + worker **must** be on a host that supports Docker (Fly.io, a VPS, or Render with Docker).

### Frontend (Vercel)

```bash
cd frontend
# Set environment variable in Vercel dashboard:
#   VITE_API_URL = https://your-backend.fly.dev
vercel deploy --prod
```

### Redis (Railway)

1. Create a Railway project → Add Redis service
2. Copy the `REDIS_URL` from Railway

### Backend + Worker (Fly.io)

```bash
# Install flyctl: https://fly.io/docs/hands-on/install-flyctl/
fly launch  # creates fly.toml
fly secrets set \
  GITHUB_CLIENT_ID=xxx \
  GITHUB_CLIENT_SECRET=xxx \
  SESSION_SECRET=xxx \
  REDIS_URL=redis://xxx \
  FRONTEND_URL=https://your-app.vercel.app \
  BACKEND_URL=https://your-app.fly.dev \
  GEMINI_API_KEY=xxx
fly deploy
```

### Update OAuth App Callback URL

After deploying, update your GitHub OAuth App's **Authorization callback URL** to:
```
https://your-backend.fly.dev/api/auth/github/callback
```

### Required Environment Variables Summary

| Variable | Backend | Frontend | Description |
|---|---|---|---|
| `GITHUB_CLIENT_ID` | ✅ | — | GitHub OAuth App Client ID |
| `GITHUB_CLIENT_SECRET` | ✅ | — | GitHub OAuth App Client Secret |
| `SESSION_SECRET` | ✅ | — | AES key for encrypting OAuth tokens (32+ chars) |
| `BACKEND_URL` | ✅ | — | Public URL of backend (no trailing slash) |
| `FRONTEND_URL` | ✅ | — | Public URL of frontend (for CORS + redirects) |
| `REDIS_URL` | ✅ | — | Redis connection string |
| `GITHUB_TOKEN` | ✅ | — | Fallback token for tasks without user OAuth |
| `GEMINI_API_KEY` | ✅ | — | At least one LLM key required |
| `GROQ_API_KEY` | ✅ | — | Optional, recommended for speed |
| `VITE_API_URL` | — | ✅ | Backend base URL (empty = same origin) |

## 🎭 Two Demo Modes

### 1. Showcase Mode (no Docker required)
Browse the UI, sign in with GitHub, view History and Dashboard. You can submit issues but the worker won't execute without Docker. Great for portfolio demos.

**Deploy frontend + backend without the Docker worker running.**

### 2. Live Execution Mode (full stack)
Requires the Docker daemon on the backend host. The worker spins up containers, executes code, and opens real PRs.

**Set all env vars including `GITHUB_TOKEN` and a valid LLM key. Run on Fly.io or a VPS.**

## 🔧 Development Notes

- **SSE auth**: EventSource can't send headers, so a one-time 60s stream token is issued via `GET /api/auth/stream-token` and passed as `?token=` query param.
- **Token security**: OAuth access tokens are stored encrypted (AES-256-GCM) in Redis with 7-day TTL. They are never logged or stored in plain text.
- **PR push auth**: The worker clones repos via `https://x-access-token:<token>@github.com/…` so each user's own token is used for all git operations, eliminating 403 push errors.
- **Dedup**: The SSE hook deduplicates events by `type:timestamp` to prevent duplicate renders on reconnect.
- **Prefers-reduced-motion**: All framer-motion animations respect `@media (prefers-reduced-motion: reduce)` via the browser's default behaviour when `animate` isn't forced.
